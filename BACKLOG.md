## Открытые задачи

### 1. Расширить тесты обработки писем

**Приоритет: высокий.** Защитить преобразование содержимого от регрессий.

- [ ] Добавить обезличенные MIME/HTML-примеры Outlook и Gmail: таблицы, цитаты, повреждённая разметка, разные кодировки.
- [ ] Проверять полноту текста, корректность Telegram-разметки и разбиение на сообщения.
- [ ] Добавить проверки фильтрации и вложений на полноценных примерах писем.

**Готово, когда:** CI обнаруживает потерю значимого содержимого и нарушение
лимитов Telegram на подготовленном наборе писем.

### 2. Подключить независимый мониторинг

**Приоритет: средний.** Выбран CronBox; код адаптирован, требуется настройка аккаунта.

- [x] Подготовить отправку сигнала после успешной обычной проверки и сохранения состояния; исключить историю и ошибки новых писем.
- [x] Добавить диагностику HTTP-ответа без раскрытия Ping URL и проверки HTTP-отправки, включая протокол CronBox.
- [x] Описать подключение и проверку предупреждения/восстановления без остановки пересылки в руководстве по эксплуатации.
- [x] Создать heartbeat-монитор CronBox в режиме отсутствия сигнала и добавить Ping URL в `HEALTHCHECK_URL` (подтверждено владельцем).
- [x] Подключить Telegram через своего бота CronBox и проверить тестовое сообщение (подтверждено владельцем).
- [ ] При необходимости подключить email как резервный канал.
- [ ] Подтвердить первый настоящий ping в истории и статус healthy после обычного запуска.
- [ ] Проверить late и реальное предупреждение при отсутствии сигналов, затем healthy и уведомление после их возобновления.

**Готово, когда:** отсутствие успешных обычных проверок обнаруживается
независимо от GitHub Actions. Секрет и тест Telegram подтверждены владельцем;
настоящий ping из workflow и оповещение об отсутствии сигналов ещё требуют проверки.
Healthchecks.io заменён после недоставки регистрационного письма.
Порядок действий — в разделе «Мониторинг» руководства по эксплуатации. Автоматическая
отмена зависших запусков в эту задачу не входит.

### 3. Упростить структуру кода и тестов

**Приоритет: средний.** Убрать побочные действия при импорте и сократить связанность.

- [ ] Вынести загрузку и проверку конфигурации из уровня импорта.
- [ ] Разделить основной скрипт на модули: конфигурация, состояние, IMAP, преобразование, Telegram, скриншоты.

**Готово, когда:** модули импортируются без секретов и сетевых подключений,
а существующие проверки сохраняют покрытие сценариев доставки.

### 4. Закрепить полное окружение

**Приоритет: низкий.** Прямые зависимости уже зафиксированы.

- [ ] Добавить полный lock-файл с транзитивными зависимостями, если потребуется воспроизводимость всего набора пакетов.
- [ ] Закрепить браузер, совместимый с выбранной версией Playwright.

**Готово, когда:** библиотеки и браузер устанавливаются в известных версиях,
а их обновления проходят автоматические проверки.

Автовосстановление очереди исключено из плана по решению владельца.
Достаточно внешнего уведомления в Telegram и ручной отмены зависшего ожидания.
Настройка бесплатного CronBox: интервал 15 минут, допуск 10 минут;
пересылка остаётся каждые 5 минут. Подробности и проверка — в руководстве по эксплуатации.

## Реализовано

Основные возможности опубликованы в `main`; новые локальные изменения
требуют публикации. Статус внешней настройки указан отдельно.

| Возможность | Результат |
| --- | --- |
| Повторы доставки | Проверки IMAP, отдельные очереди ошибок, пять попыток и ручной повтор по UID |
| Частичная отправка | Сохранение подтверждённых частей текста, вложений и ID первого сообщения |
| Защита состояния | Проверка структуры, атомарная запись, остановка при повреждении или ошибке сохранения |
| Резервная копия | Артефакт состояния при ошибке push, срок хранения — 7 дней при успешной загрузке |
| История | Отдельная позиция, фиксированная граница, продолжение порциями и намеренный перезапуск |
| Скриншоты | Блокировка внешних ресурсов, сохранение CID-картинок, ограничения HTML и размеров снимков |
| Уведомления | Личные сообщения о сбоях и исчерпании попыток, отдельный тестовый режим |
| Мониторинг | CronBox: секрет добавлен, тест Telegram успешен; настоящий ping и отсутствие сигналов ещё требуют проверки |
| Автоматические проверки | Тесты доставки, истории, состояния, мониторинга и браузера; CI и проверки перед пересылкой |
| Документация и зависимости | Структурированный README и закреплённые прямые зависимости |

## Известные ограничения

- Потеря ответа Telegram или состояния до push может привести к дублям; абсолютная гарантия однократной доставки отсутствует.
- Восстановление состояния и разбор `DeliveryPlanChanged` выполняются вручную.
- Ошибка отдельного письма не делает workflow неуспешным; результат отражается в очередях и уведомлениях. При лимите 1 новые письма имеют приоритет над повторами.
- Последний шаг уведомления может не выполниться при остановке runner. Отдельной очереди повторов уведомлений нет.
- Размеры скриншотов ограничены, но жёсткой квоты памяти браузера нет. Внешние изображения и CSS не загружаются.
