# mail2tg

Автоматическая пересылка писем из Яндекс Почты в Telegram-канал.
Бот публикует текст, вложения и скриншоты HTML-писем, сохраняя прогресс
между запусками. Работает в GitHub Actions и не требует отдельного сервера.

## Возможности

- **Новые письма** — регулярная проверка почты и публикация в канале.
- **Текст и вложения** — преобразование HTML в Telegram-разметку и разбиение длинных сообщений.
- **Скриншоты** — снимки HTML-писем с таблицами и встроенными изображениями через Playwright.
- **История** — пересылка с выбранной даты отдельными порциями с возможностью продолжения.
- **Повторы доставки** — очереди ошибок, сохранение подтверждённых этапов и ручной повтор по UID.
- **Мониторинг** — личные уведомления об ошибках и поддержка внешнего контроля через CronBox.

Почта открывается только для чтения: письма не удаляются и не помечаются прочитанными.

## Принцип работы

1. Планировщик запускает workflow проверки почты.
2. Бот получает письма по IMAP, подготавливает содержимое и отправляет его в Telegram.
3. Прогресс сохраняется в `state.json` и фиксируется в репозитории.
4. После успешной обычной проверки без ошибок новых писем отправляется сигнал внешнему монитору.

Запуски организованы через cron-job.org каждые пять минут; встроенное расписание
GitHub сохранено как дополнительный источник запусков. Фактическое время старта
зависит от доступности GitHub Actions. Workflow выполняются последовательно.

## Надёжность и ограничения

Реализованы атомарная запись и проверка состояния, отдельные позиции для новых
писем и истории, сохранение частичного прогресса отправки. После пяти неудачных
попыток письмо остаётся для ручного повтора. При ошибке публикации состояния
workflow пытается сохранить резервную копию в артефактах Actions.

Внешний монитор обнаруживает отсутствие успешных проверок независимо от workflow.
После уведомления причину проверяют в Actions; зависшее ожидание runner отменяется вручную.

- Потеря ответа Telegram или состояния до его публикации может привести к дублям.
- Ошибка отдельного письма не обязательно делает весь workflow неуспешным.
- Скриншоты не загружают внешние ресурсы и не выполняют JavaScript; оформление может отличаться от оригинала.

## Быстрый старт

Окружение workflow: **Python 3.12 · Ubuntu 24.04 · Playwright**.

1. Подготовьте репозиторий проекта, почтовый ящик Яндекса и Telegram-бота с правом публикации в канале.
2. Добавьте секреты GitHub Actions:

   | Секрет | Назначение |
   | --- | --- |
   | `IMAP_USER` | Адрес почтового ящика |
   | `IMAP_PASSWORD` | Пароль приложения Яндекса |
   | `TG_TOKEN` | Токен Telegram-бота |
   | `TG_CHAT_ID` | ID или `@username` канала |
   | `TG_ADMIN_CHAT_ID` | Необязательно: личный чат для уведомлений |
   | `HEALTHCHECK_URL` | Необязательно: секретный URL внешнего монитора |

3. Запустите **Actions → Почта → Telegram → Run workflow** с параметрами по умолчанию.
4. Настройте расписание и мониторинг по [руководству по эксплуатации](docs/OPERATIONS.md).

При пустом начальном состоянии первый обычный запуск запоминает текущую позицию
и пропускает старые письма. Для нового развёртывания нужна собственная начальная
копия `state.json` со значением `{}`. Рабочее состояние существующего развёртывания
сбрасывать нельзя. Для пересылки истории предусмотрен параметр `since`.

## Проверки качества

Тесты покрывают доставку, повторы, историю, состояние, мониторинг и ограничения
скриншотов. CI проверяет зависимости и код, включая отдельный запуск с настоящим браузером.

```bash
python -m pip install -r requirements.txt
python -B -m unittest discover -s tests -v
```

Обычные тесты не требуют секретов и сетевых подключений. Браузерные проверки
включаются отдельно; подробности — в [руководстве](docs/OPERATIONS.md#разработка-и-тесты).
